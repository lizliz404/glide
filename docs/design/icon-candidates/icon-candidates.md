# Glide extension icon — candidates (2026-11-01)

现状问题：紫蓝渐变 + 白屏幕线框 + webcam 泡，概念对但执行靠细描边——16px 糊成一坨紫。
三稿全部手工 SVG（非生图），同一块紫蓝渐变底板（`#7c5cff → #4634d8`，圆角 28/128 ≈ 22%），
一个强调色（红 `#ff5a5f` 录制语义），无描边依赖——全部实心形状。

对照：`icon-current-16/128.png` 为现行版。

## A · `icon-a-screen-rec` — 屏幕 + 录制泡（原概念改良）

实心白屏 + 红录泡压右下角，泡外 12px 白圈做底/前景分隔。
16px 读作「屏上一个红点」——录屏语义最直接，跟原图标血缘最近、替换最无感。

## B · `icon-b-glide` — 滑入镜头泡（更强概念，推荐）

月牙形渐细拖尾划入白泡，泡心一点红 = 录制中的 webcam 泡。
把产品两个签名合成一笔：**跟随镜头的滑行（glide/follow-cam）+ webcam 泡**。
16px 读作带尾的白点 = 彗星/滑行，方向感最强、最不像通用录屏图标。
风险：16px 下拖尾只有 ~1.5px，是「有动势的点」而非「能看清的弧线」——胜在动势成立。

## C · `icon-c-lens` — 镜头泡 + 录点

大白泡即 webcam bubble，紫瞳 = 镜头，右上角红录点（通知点式）。
16px 下三者里**轮廓最干净**（一个圆环 + 两点），但语义偏向「相机」，
丢掉了「屏幕」信息，也偏离原名「glide」最远。

## 建议

**B** 当主标（名字即 glide，动势独一份）；**A** 做保守备选（迁移成本最低、
与产品「屏幕+泡」UI 同构）。C 可当 fallback 若嫌 B 抽象。

## 落地提醒（选定后）

- 替换 `static/icons/{16,32,48,128}.png`；manifest 无需改路径。
- 真上生产建议按光学大师思路：16px 出独立 master（B 的拖尾可加粗至 2px 等效），
  不要只机械缩放 128 版。
